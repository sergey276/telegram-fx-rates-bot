# Telegram-бот мониторинга курсов валют и криптовалют

> **English summary.** An async Telegram bot that tracks currency and crypto rates in real time: Monobank, PrivatBank and six crypto exchanges (Binance, Bybit, OKX, Bitget, BingX, KuCoin) via public REST/WebSocket APIs. It compares sources, draws charts, sends price alerts and estimates arbitrage after fees. Stack: Python 3.12, aiogram 3, aiohttp, SQLAlchemy 2 + Alembic, PostgreSQL, Redis, matplotlib, pytest, Docker. UI languages: RU / UK / EN. Setup instructions below (in Russian); copy `.env.example` to `.env` and set `BOT_TOKEN` to run it.

Бот в реальном времени собирает курсы **Monobank, PrivatBank** и spot-котировки **Binance, Bybit, OKX, Bitget, BingX, KuCoin**,
сравнивает источники, рисует графики, шлёт уведомления и оценивает потенциальный арбитраж (с учётом комиссий).
Используются только публичные API без ключей. Подробности по эндпоинтам: [docs/API_NOTES.md](docs/API_NOTES.md).

**Стек:** Python 3.12 · aiogram 3 · aiohttp (REST + WebSocket) · PostgreSQL + SQLAlchemy 2 + Alembic · Redis · matplotlib · pydantic · pytest · Docker.

## Быстрый старт (Docker — рекомендуется)

1. Создайте бота у @BotFather (см. ниже) и узнайте свой Telegram ID (бот @userinfobot).
2. Скопируйте настройки и заполните `BOT_TOKEN`, `ADMIN_IDS`, `POSTGRES_PASSWORD`:
   ```
   copy .env.example .env        # Linux/macOS: cp .env.example .env
   notepad .env
   ```
3. Запуск (миграции БД применяются автоматически):
   ```
   docker compose up -d --build
   docker compose logs -f bot
   ```
4. Откройте бота в Telegram и отправьте `/start`.

Остановка: `docker compose down` (данные сохраняются в томах; `down -v` удалит и данные).

## Создание бота через BotFather

1. В Telegram откройте **@BotFather** → `/newbot`.
2. Введите имя (любое) и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AA...` — вставьте его в `.env` как `BOT_TOKEN`. Токен — секрет: не публикуйте его.
4. Свой числовой ID получите у @userinfobot и укажите в `ADMIN_IDS` (несколько — через запятую).
5. Меню команд бот регистрирует сам при запуске.

## Запуск на Windows

**Вариант A — Docker Desktop** (всё включено: PostgreSQL + Redis): установите Docker Desktop, затем команды из «Быстрого старта» в PowerShell.

**Вариант B — без Docker, без БД-серверов** (проще всего попробовать; SQLite + кеш в памяти):
1. Установите Python **3.12+** с python.org (галочка *Add python.exe to PATH*).
2. В папке проекта:
   ```
   py -3.12 -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   copy .env.example .env
   ```
3. В `.env` задайте `BOT_TOKEN`, `ADMIN_IDS` и `DATABASE_URL=sqlite+aiosqlite:///fxbot.db` (строку `POSTGRES_*` можно оставить).
4. `python -m app.main`

> SQLite — режим для разработки и личного использования. Для постоянной работы используйте PostgreSQL (вариант A или VPS).
> Нативный запуск на Windows в этой разработке не проверялся (проверены Linux-контейнеры и SQLite-режим внутри Linux).

**Вариант C — Python + свой PostgreSQL/Redis:** задайте `DATABASE_URL=postgresql+asyncpg://user:pass@localhost:5432/db`, `REDIS_URL=redis://localhost:6379/0`, выполните `alembic upgrade head`, затем `python -m app.main`.

## Запуск на VPS (Ubuntu 22.04/24.04)

```bash
curl -fsSL https://get.docker.com | sh            # установка Docker
git clone <ваш-репозиторий> fxbot && cd fxbot     # или скопируйте папку через scp
cp .env.example .env && nano .env                  # BOT_TOKEN, ADMIN_IDS, POSTGRES_PASSWORD
docker compose up -d --build
docker compose logs -f bot
```
* Контейнеры стартуют сами после перезагрузки (`restart: unless-stopped`, Docker включён в автозагрузку).
* Порты наружу не публикуются (бот работает через long polling) — достаточно открытого SSH.
* Обновление: `git pull && docker compose up -d --build`.
* Резервная копия: `docker compose exec -T postgres pg_dump -U fxbot fxbot > backup.sql`.
* Binance/Bybit блокируют часть стран (HTTP 403/451, например IP из США) — выбирайте VPS в ЕС либо задайте зеркала в `.env` (`BINANCE_REST_URL` и т.д.). Бот при этом продолжает работать с остальными источниками и показывает причину в `/sources`.
* Запускайте **один** экземпляр бота на токен (два polling-процесса конфликтуют).

## Как это устроено

```
 Binance/Bybit/OKX/Bitget/BingX/KuCoin ──WebSocket──┐        ┌─► Telegram-бот (aiogram)  ◄── пользователи
 те же биржи ──REST (старт, сверка, watchdog)───────┼─► QuoteStore (память + Redis) ─┤
 Monobank / PrivatBank ──REST раз в 5 мин───────────┘        ├─► Движок уведомлений
                                                             ├─► Аналитика: сравнение, арбитраж
            HistoryAggregator (минутные/часовые свечи) ─► PostgreSQL ─► Графики (matplotlib)
```

| Модуль | Назначение |
|---|---|
| `app/providers` | по провайдеру на банк/биржу, единый интерфейс; разбор ответов — чистые функции |
| `app/websocket` | потоки бирж: переподключение с backoff, keep-alive, детектор «зависшего» соединения |
| `app/collectors` | жизненный цикл источника: REST-загрузка → WebSocket → watchdog устаревших пар → сверка |
| `app/cache` | `QuoteStore` (чтение из памяти, запись-сквозь в Redis), ограничитель запросов пользователей |
| `app/database` | модели SQLAlchemy 2, репозитории; миграции — `alembic/` |
| `app/services` | пользователи, каталог пар, здоровье источников, история, глобальные настройки |
| `app/analytics` | сравнение источников и арбитраж (чистая логика) |
| `app/alerts` | движок уведомлений |
| `app/charts` | генерация графиков |
| `app/bot` | обработчики, клавиатуры, middleware, тексты |
| `app/i18n.py`, `app/config`, `app/utils` | тексты ru/uk/en, настройки (`.env`), вспомогательное |

**Единый формат котировки** (`app/domain.py::Quote`): источник, пара, `bid`, `ask`, `last`, `spread`, объём, время источника, время получения ботом, статус актуальности. Банковский курс, цена последней сделки и цена стакана хранятся в **разных полях** и не подменяют друг друга.

**Актуальность:** свежесть считается по времени получения данных ботом (биржи — 45 с, банки — 15 мин, настраивается). «Устаревшие» показываются с 🟡 и предупреждением, «неактуальные» (в 4 раза старше порога) скрываются; в минимуме/максимуме, арбитраже и уведомлениях участвуют только свежие. Если источник недоступен, остальные продолжают работу.

**Ограничения API:** запросы ограничиваются токен-бакетом по каждому источнику; Monobank — не чаще раза в 5 минут (меньше в настройках задать нельзя); `429` учитывает `Retry-After`; временные сбои — экспоненциальная пауза.

## База данных и история

Таблицы: `users`, `user_settings`, `tracked_assets`, `exchange_rates`, `bank_rates`, `price_history`, `alerts`, `alert_history`, `exchange_status` + служебные `source_errors` (для `/errors`) и `app_settings` (глобальные настройки).

WebSocket-сообщения **не пишутся** в БД по одному: каждое лишь обновляет минутную свечу в памяти; раз в 30 с свечи сбрасываются пачкой и параллельно агрегируются в часовые. `price_history` хранит свечи 1m (3 суток) и 1h (120 суток) с уникальным индексом по (источник, пара, разрешение, время). `exchange_rates` — снимок раз в минуту, `bank_rates` — только изменения курса. Старые данные удаляются автоматически (сроки — в `.env`).

## Арбитраж — как считается и чего не знает бот

Покупка на бирже A по `ask`, перевод, продажа на бирже B по `bid`:
`затраты = qty·ask·(1+fee_A+slip)`, `получено = (qty − комиссия_вывода)·bid·(1−fee_B−slip)`. Объём ограничен лучшей ценой стакана с обеих сторон и размером условной сделки (по умолчанию 1000 USDT). Показываются разница до издержек, чистая прибыль с переводом и «без перевода» (балансы заранее на обеих биржах).

**Это оценка, а не гарантированная прибыль.** Комиссии торговли и вывода — **настраиваемые оценки** (`EXCHANGE_FEES_JSON`, `WITHDRAW_FEES_JSON`): публичный API без авторизации реальные тарифы и статус ввода/вывода не отдаёт. Глубина стакана глубже лучшей цены, скорость перевода и исполнение ордеров не моделируются.

## Уведомления

Типы: цена выше/ниже, изменение на N% за период (5 мин … 24 ч, сравнение с историей), разница между биржами ≥ N%, арбитраж ≥ N% чистыми. Защита от повторов: срабатывание «по фронту» (повтор только после возврата условия в норму) + интервал (из настроек пользователя) + временное отключение сигналов (1/8/24 ч). Уведомления не отправляются по устаревшим данным.

## P2P: сравнение площадок

Раздел `💱 P2P` / `/p2p` сравнивает **цены покупки и продажи USDT, BTC и ETH за гривны** на пяти P2P-площадках: **Binance, Bybit, OKX, KuCoin, Bitget** — по способам оплаты через **Monobank, PrivatBank, Alliance, Sense Bank, A-Bank, PUMB** (карта и IBAN считаются одним банком).

* **Главный экран:** лучшая цена по каждому банку среди всех площадок («по банкам») и лучшая цена по каждой площадке среди банков («по площадкам»), самая дешёвая покупка и самая выгодная продажа.
* **Кнопка банка:** все площадки рядом для этого банка и топ-5 объявлений с лимитами, объёмом и статистикой продавца.
* **Сумма сделки** (1 000 / 5 000 / 10 000 / 50 000 ₴): показываются только объявления, в лимиты которых укладывается сумма и у которых хватает объёма. Без этого «лучшая цена вообще» вводила бы в заблуждение: выгодные объявления на покупку обычно мелкие, на продажу — крупные.
* **Фильтр надёжности:** от объявителей с не менее чем 20 сделок и 90 % завершённых.
* **Отказоустойчивость:** площадки опрашиваются параллельно, с таймаутом; если одна не ответила — остальные показываются, а у неотвечающей стоит ⚠️. При сбое показываются прошлые данные (до 10 минут) с пометкой 🟡. Результат кешируется на 60 секунд, одновременные запросы пользователей делят один обход. Первый запрос после простоя занимает 8–10 секунд.
* Администратор может выключить раздел: `/admin` → «Глобальные настройки».

**Ограничения.** Ни у одной из площадок нет официального публичного API для P2P: используются публичные веб-эндпоинты их сайтов (проверены живыми запросами). Формат может измениться без предупреждения — тогда соответствующая площадка помечается как не ответившая, остальной бот работает. Bitget отвечает HTTP 429 при частых запросах, поэтому для него выдержан медленный темп. **BingX не подключён**: его P2P-эндпоинт вернул HTTP 403. У Bybit для гривны нет способа оплаты Alliance, у большинства площадок Alliance почти не представлен — для него данных может быть мало. Цены — текущие объявления, а не гарантия сделки: они могут исчезнуть, комиссии банков, правила площадок и риск контрагента не учитываются. Разница между лучшей продажей и лучшей покупкой — не гарантированная прибыль: это разные объявления, площадки и лимиты.

## Безопасность

Секреты только в `.env` (в git не попадает), токен маскируется в логах; публичные API без ключей; лимит запросов на пользователя (Redis/память); валидация всего ввода (символы, числа, диапазоны, данные кнопок); запросы к БД только через SQLAlchemy (параметризованные); HTML-вывод экранируется; админ-функции — только для `ADMIN_IDS`; бот не запрашивает пароли, карты и ключи кошельков; бот отвечает только в личных чатах; контейнер работает не от root, порт PostgreSQL наружу не открыт.

## Известные ограничения

* **Не проверено на реальном Telegram** (токена в среде разработки не было): интерфейс проверен через Dispatcher с имитацией Bot API; первый запуск с вашим токеном — первая проверка «вживую».
* **TON/USDT** на момент проверки найден только на Binance (и без стакана); на остальных биржах пара отсутствует. Бот показывает, где пары нет, и не сравнивает её.
* PrivatBank не отдаёт время котировки, а Monobank для части пар (например GBP/UAH) — только кросс-курс; бот показывает это явно, а не выдумывает значения.
* Пересчёт цен в UAH/EUR — справочный (по курсу банка, USDT принят за USD).
* Только spot-рынки; для криптовалют поддерживаются пары к USDT.
